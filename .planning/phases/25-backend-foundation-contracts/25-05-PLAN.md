db.ts (D-12):
- DRIZZLE=go: `createDb()` does `const { drizzle } = await import('drizzle-orm/netlify-db')` and returns `drizzle({ schema })`. The adapter reads NETLIFY_DB_URL at call time and honours NETLIFY_DB_DRIVER=server for node-postgres.

- `getDb()` memoises the promise and clears the memo if creation rejects, so a cold-start failure is retried on the next request.
- Nothing runs at import.

repo.db.ts implements IngestRepository:
- insertGameRecord: one transaction. Insert games with ON CONFLICT (id) DO NOTHING RETURNING id, received_at.
  - If no row is returned, select the existing received_at and return created false without touching children.
  - Otherwise bulk-insert game_players and (if any) question_outcomes. 500 rows x 9 params stays under Postgres' 65535-param limit.
  - Map camelCase contract fields to columns explicitly. Never spread request objects into inserts.
- insertFeedback: INSERT ... ON CONFLICT DO NOTHING RETURNING (no target, so both the PK and feedback_dedupe_uq are covered).
  - On no row, select by id first, then by the dedupe tuple, and return that row's id/received_at with created false.
  - note null when absent; question_snapshot stored as JSON; client_created_at from createdAt; schema_version from schemaVersion.
- ping: `select 1`.
- receivedAt is always `date.toISOString()` from the DB value (identical replay bodies, D-06).
All SQL is parameterised through the query builder; no string concatenation of values.
